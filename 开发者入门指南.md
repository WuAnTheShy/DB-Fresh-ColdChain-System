# 第二部分：async/await 异步编程

---

## 2.1 为什么需要异步

数据库查询需要几百毫秒。如果同步等待，这段时间线程被卡住，其他用户只能排队。

```csharp
// 同步（❌ 不好）— 线程被卡住等数据库
ProductDto GetProduct(string id)
{
    var data = database.Query(id);  // 卡住 200ms
    return MapToDto(data);
}

// 异步（✅ 好）— 线程去处理其他请求，数据回来了再通知我
async Task<ProductDto> GetProductAsync(string id)
{
    var data = await database.QueryAsync(id);  // 不卡，让出线程
    return MapToDto(data);
}
```

---

## 2.2 两条规则

**规则一**：调用别人写好的异步方法时，前面加 `await`

```csharp
var result = await _service.GetProductByIdAsync("abc-123");  // await
// result 就是 ApiResponse<ProductDto>，可以直接用
```

```csharp
// 不加 await 的后果
var task = _service.GetProductByIdAsync("abc-123");  // task 是 Task<...>，不是结果
// 你拿不到真正的数据
```

**规则二**：自己方法里用了 `await`，方法签名要加 `async` + 返回类型包 `Task<>`

```csharp
// 没有 await → 不需要 async
public IActionResult Index() => View();

// 有 await → 必须加 async，返回类型写 Task<>
public async Task<IActionResult> Details(string id)
{
    var result = await _service.GetProductByIdAsync(id);  // 有 await
    return View(result.Data);
}
```

---

## 2.3 async 的传播

一旦一个方法变成 `async`，调用它的方法也必须 `await` → 也必须 `async`，一直传播到 Controller。

```
Repository.GetByIdAsync()  → async
Service.GetProductAsync()  → async（因为调了上面那个）
Controller.Details()       → async（因为调了上面那个）
```

# 第四部分：Dapper 数据库访问

---

## 4.1 Dapper 是什么

Dapper 是一个"微型 ORM"（Object-Relational Mapper）。

**不用 Dapper（原始方式）**：
```csharp
using var cmd = new OracleCommand("SELECT * FROM INV_PRODUCTS WHERE PRODUCTID = :id", conn);
cmd.Parameters.AddWithValue("id", "abc-123");
using var reader = cmd.ExecuteReader();
var product = new InvProduct();
while (reader.Read())
{
    product.ProductID = reader.GetString(0);
    product.ProductName = reader.GetString(1);
    // ... 手动映射 15 个字段
}
```

**用了 Dapper**：
```csharp
var sql = """SELECT * FROM "Inv_Products" WHERE "ProductID" = :Id""";
var product = await conn.QuerySingleOrDefaultAsync<InvProduct>(sql, new { Id = "abc-123" });
// ↑ Dapper 自动把列映射到对象属性
```

---

## 4.2 基本操作

### 查询（Query）

```csharp
// 查一条
var product = await conn.QuerySingleOrDefaultAsync<InvProduct>(
    "SELECT * FROM \"Inv_Products\" WHERE \"ProductID\" = :Id",
    new { Id = "xxx" });

// 查多条
var all = await conn.QueryAsync<InvProduct>("SELECT * FROM \"Inv_Products\"");

// 带参数
var list = await conn.QueryAsync<InvProduct>(
    "SELECT * FROM \"Inv_Products\" WHERE \"Status\" = :Status",
    new { Status = "ACTIVE" });
```

### 多表关联（Multi-mapping）

```csharp
// JOIN 两张表，Dapper 帮你拆成两个对象
var sql = """
    SELECT p.*, s.*
    FROM "Inv_Products" p
    LEFT JOIN "Inv_Suppliers" s ON p."SupplierID" = s."SupplierID"
    WHERE p."ProductID" = :Id
    """;

var product = (await conn.QueryAsync<InvProduct, InvSupplier, InvProduct>(
    sql,
    (prod, supplier) =>          // ← 这个 Lambda 告诉 Dapper 怎么拼对象
    {
        prod.Supplier = supplier;
        return prod;
    },
    new { Id = "xxx" },
    splitOn: "SupplierID"        // ← 告诉 Dapper 从哪一列开始是第二个对象
)).FirstOrDefault();
```

### 写入（Execute）

```csharp
// 插入 — 整个对象传进去，Dapper 自动匹配属性名和列名
var sql = """
    INSERT INTO "Inv_Suppliers"
        ("SupplierID", "SupplierName", "ContactPhone")
    VALUES
        (:SupplierID, :SupplierName, :ContactPhone)
    """;
await conn.ExecuteAsync(sql, supplier);

// 更新
await conn.ExecuteAsync(
    "UPDATE \"Inv_Products\" SET \"ProductName\" = :Name WHERE \"ProductID\" = :Id",
    new { Name = "新名字", Id = "xxx" });

// 删除
await conn.ExecuteAsync(
    "DELETE FROM \"Inv_Suppliers\" WHERE \"SupplierID\" = :Id",
    new { Id = "xxx" });
```

## 4.3 Oracle 注意点

| 注意 | 说明 |
|------|------|
| 参数用 `:name` | 不能用 `@name`（那是 SQL Server 的） |
| 表名列名加双引号 | `"Inv_Products"` 避免 Oracle 关键字问题 |
| `VARCHAR2` 不是 `VARCHAR` | Oracle 的字符串类型 |
| 主键自增 | 我们不用 Oracle 的 SEQUENCE，而是应用层生成 GUID |
| 分页 | `OFFSET :skip ROWS FETCH NEXT :take ROWS ONLY` |

# 第五部分：事务控制

---

## 5.1 什么是事务

事务 = 把多个数据库操作打包。要么全成功，要么全失败。

```
没有事务：
  创建产品 ✅ → 创建库存 ❌（数据库挂了）
  结果：产品创建了，库存没创建 → 数据不一致

有事务：
  Begin → 创建产品 ✅ → 创建库存 ❌ → Rollback
  结果：产品撤回，库存也没创建 → 数据一致
```

---

## 5.2 事务怎么写

### 方式一：A 组自己控制事务（内部模式）

```csharp
// A 组的 ProductInventoryService
public async Task<ApiResponse> StockOutAsync(UpdateInventoryDto dto)
{
    try
    {
        await _uow.BeginAsync();                              // 1. 开事务

        var stock = await _stockRepo.GetByProductIdForUpdateAsync(dto.ProductID);
        //                      ↑ FOR UPDATE — 行级锁（下面细说）

        if (stock.AvailableQty < dto.Quantity)
        {
            await _uow.RollbackAsync();                       // 2a. 失败就回滚
            return ApiResponse.Fail("库存不足");
        }

        stock.TotalQty -= dto.Quantity;
        _stockRepo.Update(stock);                             // 3. 写操作

        // FEFO 批次扣减
        foreach (var batch in batches)
        {
            batch.CurrentQty -= deduct;
            _batchRepo.Update(batch);
        }

        await _uow.CommitAsync();                             // 4. 全部成功 → 提交
        return ApiResponse.Success("出库成功");
    }
    catch
    {
        await _uow.RollbackAsync();                           // 任何异常 → 回滚
        throw;
    }
}
```

**关键点**：`BeginAsync()` 和 `CommitAsync()` 之间的所有 SQL 都在同一个事务里。任何一个失败，全部回滚。

---

### 方式二：B 组控制事务 + A 组执行（外部模式）

B 组下单时涉及 A 组的库存表和 B 组的订单表——这些操作需要在同一个事务里。事务由调用方 B 组控制。

```csharp
// B 组的 OrderService
public async Task<CreateOrderResult> CreateOrderAsync(CreateOrderRequest request)
{
    // _transactionManager 创建一个 IDbTransaction
    return await _transactionManager.ExecuteAsync(async transaction =>
    {
        // ↓ A 组的库存锁 — 使用 B 组的事务
        var snapshots = await _inventoryService.ReserveAsync(items, transaction);

        // ↓ B 组的订单 — 同样的事务
        await _orderRepo.CreateOrderAsync(order, transaction);

        // ↓ 全部成功后 B 组提交
        // transaction.Commit() 由 ExecuteAsync 自动调用

        return new CreateOrderResult { ... };
    });
}
```

```csharp
// A 组的 InventoryServiceAdapter — 接收 B 组的事务
public async Task<IReadOnlyList<InventoryProductSnapshot>> ReserveAsync(
    IReadOnlyList<InventoryReservationItem> items,
    IDbTransaction transaction)        // ← B 组传入的事务
{
    _uow.AttachExternalTransaction(transaction);   // ← 接上 B 组的事务

    foreach (var item in items)
    {
        var stock = await _stockRepo.GetByProductIdForUpdateAsync(item.ProductId);
        //              ↑ FOR UPDATE 走 B 组事务的连接

        stock.LockedQty += item.Quantity;
        _stockRepo.Update(stock);       // ← 走 B 组事务
    }
    // A 组不 Commit！B 组统一 Commit
}
```

**事务传递的完整链路**：

```
B 组 OrderService
  │
  ├─ _transactionManager.ExecuteAsync(transaction =>
  │    │
  │    ├─ _inventoryService.ReserveAsync(items, transaction)
  │    │     └─ A 组 InventoryServiceAdapter
  │    │          └─ _uow.AttachExternalTransaction(transaction)
  │    │               └─ 所有 Repository 操作走 B 组的连接 + 事务
  │    │
  │    ├─ _orderRepo.CreateOrderAsync(order, transaction)
  │    │     └─ 同样走这个事务
  │    │
  │    └─ ExecuteAsync 自动调用 transaction.Commit()
  │         → A 组锁库存 + B 组建订单，同时生效
  │
  └─ 如果任何一步抛异常 → transaction.Rollback()
       → A 组解锁库存 + B 组订单撤回，同时回滚
```

---

## 5.3 FOR UPDATE 行级锁

事务保证了"一起成功或一起失败"，但不能保证并发安全。

```
场景：库存只剩 5 件，两个人同时下单买 5 件

没有锁：
  请求A: 读库存(5, LockedQty=0)  ← 读到 5，可用 5-0=5 ✅
  请求B: 读库存(5, LockedQty=0)  ← 也读到 5，也认为可用 ✅
  请求A: LockedQty += 5 → 写回
  请求B: LockedQty += 5 → 写回
  结果：LockedQty = 10，但库存只有 5 → 超卖！

有 FOR UPDATE：
  请求A: SELECT ... FOR UPDATE → 锁住这一行
  请求B: SELECT ... FOR UPDATE → 被阻塞（排队等锁释放）
  请求A: LockedQty += 5 → 提交 → 释放锁
  请求B: 读库存(5, LockedQty=5)  ← 读到 LockedQty=5，可用 5-5=0 ❌
  结果：请求B 看到库存不足，返回失败 → 不会超卖
```

### FOR UPDATE 在 A 组怎么写的

```csharp
// Repositories/StockSummaryRepository.cs
public async Task<InvStockSummary?> GetByProductIdForUpdateAsync(string productId)
{
    var sql = """SELECT * FROM "Inv_StockSummary" WHERE "ProductID" = :Id FOR UPDATE""";
    //                                                                      ↑↑↑↑↑↑↑↑↑↑
    return await _uow.Connection.QuerySingleOrDefaultAsync<InvStockSummary>(
        sql, new { Id = productId }, _uow.Transaction);
    //                                ↑ 必须在事务里才生效
}
```

**FOR UPDATE 的两条规则**：
1. 必须在事务里使用（`BeginAsync()` 之后，`CommitAsync()` 之前）
2. 事务提交或回滚时自动释放锁

public class StockSummaryRepository : BaseRepository<InvStockSummary>, IStockSummaryRepository

```

// Step 2：实现接口（Services/ 目录）
public class SupplierService : ISupplierService
{
    private readonly ISupplierRepository _repo;

    public SupplierService(ISupplierRepository repo) => _repo = repo;

    public async Task<ApiResponse<List<SupplierAccountDto>>> FindSupplierAccountAsync(...)
    {
        var all = await _repo.GetAllAsync();
        var result = all.Where(s => ...).Select(s => new SupplierAccountDto { ... }).ToList();
        return ApiResponse<List<SupplierAccountDto>>.Success(result);
    }
}

// Step 3：在 Program.cs 注册（告诉框架：当有人要 ISupplierService 时，给 SupplierService）
builder.Services.AddScoped<ISupplierService, SupplierService>();

// Step 4：在需要的地方注入使用
public class SomeController : Controller
{
    private readonly ISupplierService _supplierService;

    public SomeController(ISupplierService supplierService)
    {
        _supplierService = supplierService;
    }
}
```

## 6.4 跨组接口 vs 内部接口

| | 内部接口 | 跨组接口 |
|---|---------|---------|
| 谁用 | A 组自己 | B 组、C 组 |
| 文件位置 | `Interfaces/ISupplierService.cs` | `Interfaces/B组_IInventoryService.cs` |
| 事务归属 | A 组自己管 | 调用方（B 组）管 |
| 返回格式 | `ApiResponse<T>` | 直接返回 `T` 或抛异常 |

**跨组接口约定**：
- B 组传入 `IDbTransaction`，A 组使用它操作，B 组控制提交/回滚
- 失败时抛异常（如 `InvalidOperationException`），B 组的事务管理器自动回滚
- 方法签名包含 `CancellationToken`，支持取消

# 第七部分：API 返回格式

---

## 7.1 ApiResponse<T> 是什么

A 组内部用的统一返回格式。所有 Service 方法都返回它。

```csharp
public class ApiResponse<T>
{
    public int Code { get; set; }         // 200 = 成功，400 = 业务错误，404 = 不存在
    public string Message { get; set; }   // 提示信息
    public T? Data { get; set; }          // 实际数据
    public bool IsSuccess => Code == 200; // 是否成功
}
```

### 怎么用

```csharp
// Service 层
public async Task<ApiResponse<ProductDto>> GetProductByIdAsync(string id)
{
    var product = await _repo.GetByIdAsync(id);
    if (product == null)
        return ApiResponse<ProductDto>.Fail("产品不存在", 404);     // 失败
    return ApiResponse<ProductDto>.Success(MapToDto(product));       // 成功
}

// Controller 层
public async Task<IActionResult> Details(string id)
{
    var result = await _service.GetProductByIdAsync(id);
    if (!result.IsSuccess)
        return NotFound(result.Message);     // 404 页面
    return View(result.Data);                // 把数据传给 .cshtml
}
```

### 不带泛型的 ApiResponse

```csharp
// 不需要返回数据时用（如删除）
return ApiResponse.Success("删除成功");
return ApiResponse.Fail("不存在", 404);
```

---

## 7.2 PagedResult<T> 分页

```csharp
public class PagedResult<T>
{
    public int PageIndex { get; set; }
    public int PageSize { get; set; }
    public int TotalCount { get; set; }
    public int TotalPages => (int)Math.Ceiling(TotalCount / (double)PageSize);
    public List<T> Items { get; set; }
}
```

### 跨组接口不用 ApiResponse

跨组接口（B 组调 A 组）不返回 `ApiResponse<T>`，而是直接返回 `T` 或抛异常。因为 B 组的事务管理器靠异常来触发回滚。

```csharp
// 内部接口（A 组自己）
Task<ApiResponse<int>> GetProductStockAsync(string productId);  // 返回 ApiResponse

// 跨组接口（B 组调 A 组）
Task<IReadOnlyList<InventoryProductSnapshot>> ReserveAsync(...); // 直接返回或抛异常
```

# 第八部分：依赖注入原理

---

## 8.1 DI 容器怎么工作

```
Program.cs 注册时：
  builder.Services.AddScoped<IProductService, ProductService>();

框架内部维护了一张字典：
  { IProductService → ProductService }

当 HTTP 请求来了，框架要 new ProductsController：
  1. 看构造函数：ProductsController(IProductService service)
  2. 查字典：IProductService → ProductService
  3. new ProductService(...) → 递归解析 ProductService 的依赖
  4. new ProductsController(service) → 完成

请求结束时自动释放 Scoped 对象。
```

# 第十部分：BaseRepository 原理

---

## 10.1 反射自动生成 SQL

`BaseRepository<T>` 是 A 组的核心基础设施。它通过 C# 的**反射**特性，在运行时读取 `[Table]`、`[Column]`、`[Key]` 注解，自动拼接 SQL。

### 第一步：实体类加上注解

```csharp
[Table("Inv_Suppliers")]              // ← 数据库表名
public class InvSupplier
{
    [Key]                              // ← 我是主键
    [Column("SupplierID")]             // ← 数据库列名
    public string SupplierID { get; set; }

    [Column("SupplierName")]
    public string SupplierName { get; set; }

    [Column("CreditLevel")]
    public int CreditLevel { get; set; }

    [NotMapped]                        // ← 不是数据库字段，跳过我
    public int ProductCount { get; set; }
}
```

### 第二步：BaseRepository 在构造时读取这些注解

```csharp
public BaseRepository(IUnitOfWork uow)
{
    var type = typeof(T);

    // 读 [Table] 注解 → 拿到表名
    var tableAttr = type.GetCustomAttribute<TableAttribute>();
    _tableName = $"\"{tableAttr.Name}\"";     // → "Inv_Suppliers"

    // 读 [Key] 注解 → 找到主键属性
    var keyProp = props.First(p => p.GetCustomAttribute<KeyAttribute>() != null);
    _keyProp = keyProp;                        // → SupplierID 属性

    // 读 [Column] 注解 → 建立 属性名 ↔ 列名 的映射
    foreach (var prop in props.Where(p => p.GetCustomAttribute<NotMappedAttribute>() == null))
    {
        var colName = $"\"{prop.GetCustomAttribute<ColumnAttribute>().Name}\"";
        _columns.Add(new MappedColumn(prop.Name, colName, prop));
    }
}
```

### 第三步：运行时自动拼 SQL

```csharp
// GetByIdAsync 自动拼成：
// SELECT * FROM "Inv_Suppliers" WHERE "SupplierID" = :Id

// AddAsync 自动拼成：
// INSERT INTO "Inv_Suppliers" ("SupplierID", "SupplierName", "CreditLevel", ...)
// VALUES (:SupplierID, :SupplierName, :CreditLevel, ...)

// Update 自动拼成：
// UPDATE "Inv_Suppliers"
// SET "SupplierName" = :SupplierName, "CreditLevel" = :CreditLevel, ...
// WHERE "SupplierID" = :SupplierID
```

### 所以这 8 行就够了

```csharp
public class SupplierRepository : BaseRepository<InvSupplier>, ISupplierRepository
{
    public SupplierRepository(IUnitOfWork uow) : base(uow) { }

    // 继承的自动方法：GetByIdAsync, GetAllAsync, GetPagedAsync, CountAsync, AddAsync, Update, Delete

    // 只有特殊查询才手写 SQL
    public async Task<InvSupplier?> GetByIdWithProductsAsync(string id) { ... }
}
```
